Experiments & Notebooks¶

The experimental pipeline is a sequence of numbered Jupyter notebooks, running simple to complex: each one imports the shared infrastructure (API Reference) and loads the cached artifacts produced by the previous one. The pages below are rendered from src/*.ipynb (notebooks live in src/ and are symlinked into docs/notebooks/ at build time by make -C docs notebooks; they are rendered with their stored outputs, never re-executed by the docs build — run them yourself as described in Installation & Quickstart).

Module-level infrastructure¶

Module

Purpose

mnesis_boilerplate

Shared imports, device detection (MPS / CUDA / CPU), random-seed utilities, Params dataclass, and helper functions reused by all downstream notebooks.

mnesis_chains

Defines SpikingPattern, StochasticSpikingPattern, and the HD_SNN class with analytical weight initialisation (pseudo-inverse or Hebbian cross-correlation, optionally deconvolving the LIF membrane). Corresponds to the Methods section of the paper.

Generative model¶

  • Generative model for spiking targets

  • Generative model for spiking targets — implements the generative model for synthetic sparse patterns: draws Gaussian logit maps \(\ell \sim \mathcal{N}(0, E_\mathrm{SM})\), thresholds to keep the top \(p_\mathrm{SM}\) fraction, convolves with the biphasic spike shape, and samples Bernoulli spike trains at rate \(p_A\). Produces the frozen and two_ssp figures and the cached artifacts used by all downstream notebooks.

Learning and retrieval on synthetic motifs¶

  • Learning a synthetic spike pattern
  • Testing inference: multiple patterns in a long sequence

  • Learning a synthetic spike pattern — trains the network on \(M = 16\) synthetic sparse patterns. Demonstrates that the analytical init alone reaches high \(F_1\); gradient training with a cosine schedule then improves noise robustness. Figures: pattern, target_init, target.

  • Testing inference: multiple patterns in a long sequence — concatenates all \(M = 16\) patterns in sequence with \(N_\mathrm{pretime} = 50\) steps of spontaneous inter-trial activity; evaluates sliding-window \(F_1\) to confirm selective, cross-interference-free retrieval. Figure: retrieval (plus .mp4).

Robustness tests¶

  • Testing robustness to input noise (p_flip)
  • Control: re-train the network for each noise level to improve WM
  • Testing inference: how long must the trigger be?
  • Testing inference: how many neurons must the trigger recruit?

  • Testing robustness to input noise (p_flip) — bit-flip noise on the trigger window (\(p_\mathrm{flip} \in [0, 1]\)). Quantifies attractor-like robustness: \(F_1 = 0.967\) at \(p_\mathrm{flip} = 0.25\), chance only near \(0.5\).

  • Testing inference: how long must the trigger be? — truncated trigger window (0 to \(D-1\) steps); finds the minimum cue length for reliable recall: \(F_1 = 0.862\) at 75% of \(D\).

  • Testing inference: how many neurons must the trigger recruit? — partial neuron coverage (0 to \(N\) neurons silenced in the trigger); perfect recall is maintained with 87.5% of neurons active.

Parameter scans & optimisation¶

  • scanning parameters
  • optimizing learning parameters with optuna

  • scanning parameters — systematic one-at-a-time scans over \(D\), \(T\), \(p_A\), \(N\), \(E_\mathrm{SM}\), \(p_\mathrm{SM}\), and the do_pinv / do_deconv flags, with \(N_\mathrm{cv} = 10\) seeds; produces the parameter-scan figures of the paper.

  • optimizing learning parameters with optuna — automated hyperparameter search with Optuna over learning dynamics, thresholds, and regularisation.

Note

The scan/optimisation notebooks use file-based locking: a .lock sentinel guards against concurrent runs of the same scan, computed parameter values are appended incrementally to the JSON, and runs can be safely resumed. See installation.

  • Notebook summary — builds periodic targets, trains periodic memories, and evaluates retrieval robustness under increasing input noise.

  • defining traveling waves patterns — MotionClouds-based travelling-wave patterns; benchmarks retrieval with structured spatiotemporal motifs.

  • working memory with the Lorenz attractor — encodes Lorenz chaotic trajectories into spike codes and evaluates memory recall on non-periodic continuous dynamics.

  • working memory with text — tokenises a Wikipedia corpus (tiktoken, cl100k_base) into token IDs, builds a frequency-ordered spike codebook (most-frequent tokens get the sparsest neuron rows, minimising the Hamming distance), wraps it in a TextSpikingPattern generator, learns and recalls the resulting spike patterns, then decodes the output spikes back to text via the inverse codebook + tokenizer. Includes Optuna tuning and parameter scans.

  • working memory with text / working memory with text — variants of the text experiment on a fixed Alice-in-Wonderland-style corpus (the one-hot version encodes tokens as one-hot spike patterns).

  • defining patterns as some Spiking Heidelberg Digits — Spiking Heidelberg Digits data loading/preprocessing for dataset-grounded experiments with real spiking recordings.
